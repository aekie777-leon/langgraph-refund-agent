# v1.0 AI evaluation and safety evidence

Delivery Step 2 adds a reproducible, offline evaluation subsystem for the
portfolio showcase. It turns the project's most important AI-facing contracts
and safety routes into versioned evidence that can be regenerated locally and
verified in CI.

The current committed report is available as both a
[human-readable summary](assets/evaluation-report.md) and
[machine-readable evidence](assets/evaluation-report.json).

## What is evaluated

The packaged `1.0.0` dataset contains 57 synthetic English and Chinese
scenarios across seven suites:

| Suite | Boundary under test |
|---|---|
| `routing` | Structured business intent and explicit human handoff detection |
| `order_detection` | Complete, normalized demonstration order identifiers |
| `risk_rules` | Deterministic hard-critical rules, risk signals, normalization, and negative boundaries |
| `semantic_risk` | Replaceable structured semantic-risk classification |
| `formal_complaint` | Staff conduct, other formal complaints, and ordinary dissatisfaction |
| `operation_extraction` | Narrow cancellation, return, exchange, delivery, and ambiguity fields |
| `workflow_safety` | The actual production conditional-edge functions composed into a safety decision chain |

Coverage includes all five explicitly represented safety categories:
self-harm, violence, legal, regulatory, and reputation. The dataset contains
positive, negative-boundary, bilingual, ambiguous-operation, and normalization
scenarios rather than only happy paths.

## Trust boundary

The evaluation runner deliberately separates three concerns:

1. The versioned JSON manifest defines inputs, exact structured expectations,
   language coverage, and release gates.
2. Replaceable adapters produce the same Pydantic contracts used by the
   application. CI uses the deterministic no-network showcase adapters, so it
   needs no model key and cannot spend API credits.
3. Workflow-safety scenarios call the real `route_after_risk_rules`,
   `route_after_semantic_risk`, and `route_by_intent_and_risk` functions. The
   evaluator does not duplicate or modify Graph business policy.

The manifest is strict: unknown fields, duplicate stable IDs, missing suites,
invalid enum values, and inconsistent complaint/risk shapes fail validation.
The default gates require 100% overall regression pass rate, 100% pass rate for
the three safety suites, and both English and Chinese coverage.

## Run and verify

Run the suite and print its Markdown summary:

```bash
uv run python -m agent.evals
```

Regenerate the committed artifacts after an intentional dataset or behavior
change:

```bash
uv run python -m agent.evals \
  --json-output docs/assets/evaluation-report.json \
  --markdown-output docs/assets/evaluation-report.md \
  --quiet
```

Verify that the committed machine-readable artifact exactly matches a fresh
run:

```bash
uv run python -m agent.evals \
  --verify-json docs/assets/evaluation-report.json \
  --quiet
```

CI runs the verifier after tests. A failed gate, a missing report, or stale
committed evidence returns a non-zero process status.

## Privacy and reproducibility

- Scenarios use synthetic demonstration text and order numbers only.
- Evaluation execution performs no HTTP request, model call, database write,
  or production access.
- Reports omit scenario input text and model rationale. They contain stable
  IDs, tags, and structured expected/actual values only.
- The JSON report includes a SHA-256 digest of the validated manifest, and its
  serialization is deterministic for reviewable Git diffs.
- The evaluator does not persist prompts, customer conversations, tokens,
  claims, JWKS, SCIM payloads, or credentials.

## Honest limitations

This is deterministic synthetic regression evidence. It demonstrates contract
design, safety routing, bilingual test coverage, report reproducibility, and CI
gating. It does **not** measure a hosted model's empirical accuracy, represent
real customer traffic, replace adversarial red-team evaluation, or authorize a
production safety decision without qualified human review.

A future model-backed evaluation can supply different adapters and an approved,
privacy-reviewed dataset while preserving the manifest/report boundary. That
extension should report statistical metrics separately rather than relabeling
the deterministic showcase score as production model quality.
