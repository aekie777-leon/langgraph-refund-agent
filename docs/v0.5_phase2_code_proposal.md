# v0.5 Phase Two Code Proposal

Status: **Archived proposal — superseded by the implemented phase-two domain package**

Scope: domain models, deterministic policy, Provider protocol, offline fake,
and unit tests. This document is retained as review history; the implemented
package now uses a seven-calendar-day window instead of the earlier business-day
proposal. Database, LangGraph graph, nodes, routing, prompts, and the existing
refund flow remain unchanged.

## 1. File plan

```text
src/agent/operations/
|-- __init__.py
|-- models.py       # Typed order snapshot, requests, decisions, statuses
|-- policy.py       # Pure cancellation/return/exchange/delivery decisions
`-- provider.py     # Async Provider protocols only

tests/fakes/
|-- __init__.py
`-- operations.py   # In-memory Provider fake for tests only

tests/unit_tests/
|-- test_operation_models.py
|-- test_operation_policy.py
`-- test_operation_provider.py
```

`agent.operations` is deliberately separate from `agent.cases`:

- an order operation is a customer request to cancel, return, or exchange;
- a support case is an internal human-work item;
- phase two returns a `CaseRecommendation` only; it does not create a case;
- phase three will add the database representation and extend the existing
  support-case types in the same migration that makes them persistable.

This prevents the Python model from accepting a new case type while the current
PostgreSQL constraint still rejects it.

## 2. Proposed `models.py`

```python
"""Define typed order-operation domain contracts."""

from datetime import date, datetime
from decimal import Decimal
from typing import Literal, Self

from pydantic import AwareDatetime, BaseModel, ConfigDict, Field, model_validator

OrderStatus = Literal["pending_payment", "confirmed", "cancelled", "completed"]
PaymentStatus = Literal[
    "unpaid",
    "paid",
    "refund_pending",
    "partially_refunded",
    "refunded",
]
FulfillmentStatus = Literal["unfulfilled", "processing", "shipped", "delivered"]
OperationType = Literal["cancellation", "return", "exchange"]
OperationStatus = Literal[
    "submitted",
    "processing",
    "manual_review",
    "completed",
    "rejected",
]
ExistingOperationType = Literal["refund", "cancellation", "return", "exchange"]
DeliveryIssueType = Literal[
    "delayed",
    "tracking_stalled",
    "delivery_failed",
    "marked_delivered_not_received",
    "package_damaged",
    "wrong_item_or_missing_parts",
    "other_delivery_issue",
]
CancellationReason = Literal[
    "ordered_by_mistake",
    "no_longer_needed",
    "incorrect_item_or_quantity",
    "delivery_too_slow",
    "payment_issue",
    "other",
]
ReturnExchangeReason = Literal[
    "changed_mind",
    "wrong_item_received",
    "damaged_item",
    "defective_item",
    "missing_parts",
    "not_as_described",
    "size_or_variant_issue",
    "other",
]
OperationReason = CancellationReason | ReturnExchangeReason
OperationOutcome = Literal[
    "eligible",
    "manual_review",
    "rejected",
    "existing_operation",
]
DeliveryOutcome = Literal["self_service", "manual_review", "offer_return_exchange"]
RecommendedCaseType = Literal[
    "order_operation_review",
    "delivery_investigation",
]
CasePriority = Literal["p0", "p1", "p2", "p3"]


class ExistingOperation(BaseModel):
    """Summarize an operation already recorded by an order system."""

    model_config = ConfigDict(extra="forbid", frozen=True)

    operation_id: str = Field(min_length=1)
    operation_type: ExistingOperationType
    status: OperationStatus
    provider_reference: str | None = Field(default=None, min_length=1)


class OrderSnapshot(BaseModel):
    """Represent the read-only facts used by deterministic operation policy."""

    model_config = ConfigDict(extra="forbid", frozen=True)

    order_id: str = Field(pattern=r"^ORD-\d{5}$")
    version: int = Field(ge=1)
    amount: Decimal = Field(ge=0, max_digits=12, decimal_places=2)
    currency: str = Field(pattern=r"^[A-Z]{3}$")
    order_status: OrderStatus
    payment_status: PaymentStatus
    fulfillment_status: FulfillmentStatus
    created_at: AwareDatetime
    shipped_at: AwareDatetime | None = None
    delivered_at: AwareDatetime | None = None
    promised_delivery_at: AwareDatetime | None = None
    last_tracking_event_at: AwareDatetime | None = None
    return_eligible: bool | None = None
    exchange_eligible: bool | None = None
    existing_operations: tuple[ExistingOperation, ...] = Field(default_factory=tuple)


class OrderOperationRequest(BaseModel):
    """Represent one normalized cancellation, return, or exchange request."""

    model_config = ConfigDict(extra="forbid", frozen=True, str_strip_whitespace=True)

    thread_id: str = Field(min_length=1)
    source_message_id: str = Field(min_length=1)
    order_id: str = Field(pattern=r"^ORD-\d{5}$")
    operation_type: OperationType
    reason: OperationReason
    replacement_variant_id: str | None = Field(default=None, min_length=1)

    @model_validator(mode="after")
    def validate_operation_specific_fields(self) -> Self:
        """Keep reason codes and exchange data valid for the requested operation."""
        cancellation_reasons = {
            "ordered_by_mistake", "no_longer_needed", "incorrect_item_or_quantity",
            "delivery_too_slow", "payment_issue", "other",
        }
        if self.operation_type == "cancellation":
            if self.reason not in cancellation_reasons:
                raise ValueError("a cancellation must use a cancellation reason")
            if self.replacement_variant_id is not None:
                raise ValueError("only an exchange may include replacement_variant_id")
        elif self.reason in cancellation_reasons - {"other"}:
            raise ValueError("a return or exchange must use a return/exchange reason")
        if self.operation_type == "exchange" and self.replacement_variant_id is None:
            raise ValueError("an exchange requires replacement_variant_id")
        return self


class DeliveryIssueRequest(BaseModel):
    """Represent a normalized delivery issue; claims are not proof of fault."""

    model_config = ConfigDict(extra="forbid", frozen=True, str_strip_whitespace=True)

    thread_id: str = Field(min_length=1)
    source_message_id: str = Field(min_length=1)
    order_id: str = Field(pattern=r"^ORD-\d{5}$")
    issue_type: DeliveryIssueType
    investigation_requested: bool = False


class CaseRecommendation(BaseModel):
    """Describe a future support-case request without persisting a case."""

    model_config = ConfigDict(extra="forbid", frozen=True)

    case_type: RecommendedCaseType
    priority: CasePriority
    reason_codes: tuple[str, ...] = Field(min_length=1)


class OperationDecision(BaseModel):
    """Return a deterministic decision for one state-changing operation."""

    model_config = ConfigDict(extra="forbid", frozen=True)

    outcome: OperationOutcome
    operation_type: OperationType
    requires_confirmation: bool = False
    reason_codes: tuple[str, ...] = Field(min_length=1)
    display_reason: str = Field(min_length=1)
    existing_operation: ExistingOperation | None = None
    case_recommendation: CaseRecommendation | None = None

    @model_validator(mode="after")
    def validate_outcome_fields(self) -> Self:
        """Keep the result shape consistent with its deterministic outcome."""
        if self.outcome == "existing_operation":
            if self.existing_operation is None:
                raise ValueError("existing_operation outcome requires an operation")
            if self.requires_confirmation or self.case_recommendation is not None:
                raise ValueError("an existing operation cannot request confirmation or a case")
        elif self.existing_operation is not None:
            raise ValueError("only existing_operation may contain an existing operation")
        if self.outcome == "eligible" and not self.requires_confirmation:
            raise ValueError("an eligible operation requires confirmation")
        return self


class DeliveryDecision(BaseModel):
    """Return a deterministic assessment for a delivery issue."""

    model_config = ConfigDict(extra="forbid", frozen=True)

    outcome: DeliveryOutcome
    issue_type: DeliveryIssueType
    reason_codes: tuple[str, ...] = Field(min_length=1)
    display_reason: str = Field(min_length=1)
    case_recommendation: CaseRecommendation | None = None


```

Important design detail: `OrderSnapshot` intentionally does **not** reject
cross-field contradictions such as `cancelled` plus `shipped`. Such data can
come from an upstream system. The policy must see it and return a safe manual
review instead of treating malformed upstream data as an unhandled validation
error.

## 3. Proposed `policy.py`

The module is pure: no database access, clock access, LLM call, or Provider call.
It receives `now` and all structured facts as parameters, which keeps tests
deterministic.

```python
"""Apply deterministic policies for order operations and delivery issues."""

from datetime import datetime
from decimal import Decimal

from agent.operations.models import (
    CaseRecommendation,
    DeliveryDecision,
    DeliveryIssueRequest,
    ExistingOperation,
    OperationDecision,
    OrderOperationRequest,
    OrderSnapshot,
)

RETURN_WINDOW_DAYS = 7
TRACKING_STALLED_HOURS = 72


class CurrencyThresholds:
    """Supply manual-review amounts as Decimal values keyed by ISO currency."""

    def __init__(self, thresholds: dict[str, Decimal]) -> None:
        self._thresholds = thresholds

    def threshold_for(self, currency: str) -> Decimal | None:
        """Return the configured threshold, if any, for a currency."""
        return self._thresholds.get(currency)


def evaluate_operation(
    request: OrderOperationRequest,
    snapshot: OrderSnapshot,
    *,
    now: datetime,
    thresholds: CurrencyThresholds,
    replacement_available: bool | None = None,
) -> OperationDecision:
    """Return the policy result for a matching request and order snapshot."""
    if request.order_id != snapshot.order_id:
        raise ValueError("request and snapshot must have the same order_id")
    _require_aware_datetime(now)
    if _has_contradictory_lifecycle(snapshot):
        return _manual(request.operation_type, "order_state_invalid", "Order state needs manual review.", "p1")

    existing = _conflicting_operation(snapshot, request.operation_type)
    if existing is not None:
        return _existing(request.operation_type, existing)

    if request.operation_type == "cancellation":
        return _evaluate_cancellation(request, snapshot)
    if request.operation_type == "return":
        return _evaluate_return_or_exchange(request, snapshot, now, thresholds)
    return _evaluate_exchange(request, snapshot, now, thresholds, replacement_available)


def evaluate_delivery_issue(
    request: DeliveryIssueRequest,
    snapshot: OrderSnapshot,
    *,
    now: datetime,
) -> DeliveryDecision:
    """Return a deterministic assessment without claiming unverified fault."""
    if request.order_id != snapshot.order_id:
        raise ValueError("request and snapshot must have the same order_id")
    _require_aware_datetime(now)
    if _has_contradictory_lifecycle(snapshot):
        return _delivery_manual(request.issue_type, "delivery_data_invalid", "Delivery data needs investigation.", "p1")

    if request.issue_type == "tracking_stalled":
        if snapshot.fulfillment_status != "shipped" or snapshot.last_tracking_event_at is None:
            return _delivery_manual(request.issue_type, "delivery_data_invalid", "Tracking data needs investigation.", "p1")
        elapsed = now - snapshot.last_tracking_event_at
        if elapsed.total_seconds() >= TRACKING_STALLED_HOURS * 3600:
            return _delivery_manual(request.issue_type, "delivery_tracking_stalled", "Tracking has not updated for 72 hours.", "p1")
        return _delivery_self_service(request.issue_type, "delivery_tracking_recent", "Tracking is still updating.")

    if request.issue_type == "delayed":
        if snapshot.promised_delivery_at is None:
            return _delivery_manual(request.issue_type, "delivery_data_invalid", "Delivery timing needs investigation.", "p1")
        if snapshot.fulfillment_status == "delivered" or now <= snapshot.promised_delivery_at:
            return _delivery_self_service(request.issue_type, "delivery_not_overdue", "The order is not confirmed as overdue.")
        if request.investigation_requested or snapshot.last_tracking_event_at is None:
            return _delivery_manual(request.issue_type, "delivery_overdue_investigation", "The delayed delivery needs investigation.", "p2")
        return _delivery_self_service(request.issue_type, "delivery_overdue", "The order is delayed; current tracking is available.")

    if request.issue_type == "delivery_failed":
        return _delivery_manual(request.issue_type, "delivery_failed", "Delivery needs a redelivery or address review.", "p2")
    if request.issue_type == "marked_delivered_not_received":
        return _delivery_manual(request.issue_type, "delivery_marked_received_dispute", "Your delivery report needs investigation.", "p1")
    if request.issue_type == "package_damaged":
        return _delivery_manual(request.issue_type, "delivery_damage_claim", "Your damage report needs review.", "p1")
    if request.issue_type == "wrong_item_or_missing_parts":
        return DeliveryDecision(
            outcome="offer_return_exchange",
            issue_type=request.issue_type,
            reason_codes=("delivery_wrong_item_or_missing_parts_claim",),
            display_reason="We can evaluate a return or exchange request.",
        )
    return _delivery_manual(request.issue_type, "delivery_other_issue", "Your delivery report needs review.", "p2")
```

The proposal uses small private helpers—`_manual`, `_existing`,
`_evaluate_cancellation`, `_evaluate_return_or_exchange`, `_evaluate_exchange`,
`_has_contradictory_lifecycle`, and delivery-result builders—to avoid repeating
the result shape. Those helpers do not perform I/O.

The key outcomes are fixed by the approved matrix:

| Condition | `OperationDecision` |
| --- | --- |
| Eligible cancellation/return/exchange | `eligible`, `requires_confirmation=True` |
| Warehouse processing cancellation | `manual_review`, confirmation required, `order_operation_review/p1` |
| High-value return or unknown exchange stock | `manual_review`, confirmation required, appropriate case recommendation |
| Missing, stale, contradictory, or unsupported-currency data | `manual_review`, no automatic mutation |
| Shipped/delivered cancellation or expired return window | `rejected` |
| Existing duplicate/conflicting operation | `existing_operation`, no confirmation |

The return and exchange deadline is calculated as `delivered_at + timedelta(days=7)`.
The exact deadline instant remains eligible; only `now > deadline` is expired.

## 4. Proposed `provider.py`

```python
"""Define the external order-system boundary without choosing an implementation."""

from typing import Protocol

from agent.operations.models import (
    ExistingOperation,
    OrderOperationRequest,
    OrderSnapshot,
)


class OrderProvider(Protocol):
    """Read current order facts and submit confirmed customer operations."""

    async def get_order(self, order_id: str) -> OrderSnapshot | None:
        """Return the current snapshot, or None when the order does not exist."""
        ...

    async def get_replacement_availability(
        self,
        *,
        order_id: str,
        replacement_variant_id: str,
    ) -> bool | None:
        """Return replacement availability; None means the provider cannot determine it."""
        ...

    async def submit_operation(
        self,
        *,
        request: OrderOperationRequest,
        expected_order_version: int,
        idempotency_key: str,
    ) -> ExistingOperation:
        """Submit one confirmed operation or report a provider-level conflict."""
        ...
```

The Protocol makes the later PostgreSQL/demo provider and a real OMS adapter
interchangeable. It deliberately does not return raw third-party JSON to graph
nodes. The Provider translates that data into `OrderSnapshot` at the boundary.

## 5. Offline fake and tests

`tests/fakes/operations.py` will use dictionaries and a lock to emulate:

- order lookup;
- variant availability lookup;
- submission keyed by idempotency key;
- rejection of a stale `expected_order_version`.

No fake data is persisted outside the test process. The tests are therefore
offline and do not require Docker, PostgreSQL, API keys, or a model.

The test suite will cover at least:

| Test area | Examples |
| --- | --- |
| Model validation | exchange needs a replacement variant; cancellation cannot use a return-only reason; decision shape is internally consistent |
| Return-window boundary | exact `delivered_at + 7 days` remains eligible; one microsecond later is expired |
| Cancellation | unfulfilled eligible; processing -> `p1` manual; shipped/delivered rejected; cancelled duplicate; contradictory snapshot -> manual |
| Return | exact seventh-day deadline eligible; one microsecond later rejected; USD 100 threshold; unsupported currency manual; already-refunded/active operation protected |
| Exchange | available eligible; unknown availability -> `p2`; unavailable rejected; duplicate return/refund conflict protected |
| Delivery | 72-hour stalled boundary; 71:59 not stalled; overdue delivery; delivered-not-received `p1`; unverified claims do not assert fault |
| Provider fake | idempotent submission returns the original operation; stale version is rejected |

# v0.5 阶段二代码方案

状态：**归档方案——已由阶段二领域包的实际实现取代**。

范围：领域模型、确定性 policy、Provider Protocol、离线 fake 和单元测试。
本方案不修改数据库、LangGraph Graph、节点、路由、提示词或现有退款流程。

## 1. 文件规划

新增独立的 `agent.operations` 包，而不是把订单操作放进 `agent.cases`：

- 订单操作是用户发起的取消、退货或换货请求；
- support case 是内部人工处理对象；
- 阶段二只返回 `CaseRecommendation`，不会真正创建工单；
- 阶段三会在同一批数据库迁移中扩展真正可持久化的 case type。

这样可以避免 Python 先接受新工单类型，但当前 PostgreSQL 约束还拒绝它的状态
不一致问题。

## 2. `models.py` 的职责

上方代码中的模型将严格分开：

- `OrderSnapshot`：Provider 读到的当前订单事实；
- `OrderOperationRequest`：已经标准化的取消、退货、换货请求；
- `DeliveryIssueRequest`：已经标准化的物流问题；
- `OperationDecision` / `DeliveryDecision`：policy 输出，Graph 后续只消费结果；
- `CaseRecommendation`：未来建单建议，不触发写库；

`OrderSnapshot` 只验证字段形状，不提前拒绝上游系统的跨字段矛盾数据。原因是
`cancelled + shipped` 这类数据必须被 policy 安全地转人工，而不是让 Pydantic
异常中断客户流程。

## 3. 七个自然日算法

退换货截止时刻为 `delivered_at + timedelta(days=7)`。该精确时刻仍然符合资格，
只有 `now > deadline` 才算到期。阶段二不调用系统当前时间，所有 policy 都由调用
方传入 `now`，因此边界测试不会因执行时间而波动。

## 4. policy 的职责

`policy.py` 保持纯函数：不读数据库、不调用 Provider、不调用 LLM。

- 符合资格的取消、退货、换货输出 `eligible` 且强制确认；
- 仓库处理中取消、金额达到阈值退货、库存未知换货输出 `manual_review`；
- 发货/送达后的取消、超出退货期限等输出 `rejected`；
- 已存在的重复或资金冲突操作输出 `existing_operation`；
- 异常订单数据和未配置币种不执行自动操作，安全地转人工；
- 物流问题区分可验证事实与用户 claim，绝不把用户说“丢件”直接当作已证实责任。

## 5. Provider 边界

`OrderProvider` 是异步 Protocol，不决定用 PostgreSQL、HTTP 还是客户现有 OMS。
任何外部 JSON 都必须先转换成 `OrderSnapshot`，Graph 不直接依赖第三方格式。

它包含三种能力：读取订单、查询换货库存、带 `expected_order_version` 和幂等键
提交已确认操作。

## 6. 测试

会新增纯内存 fake，覆盖幂等提交和订单版本冲突。所有阶段二单元测试均离线运行，
不依赖 Docker、PostgreSQL、API Key 或 LLM。

重点边界包括：送达后第 7 天精确时刻与其后一微秒、72 小时整与 71 小时 59 分、USD 100 阈值、
未配置币种、重复退款/退货/换货、上游状态矛盾、库存未知及确认要求。

## 7. 阶段二明确不改的文件

`graph.py`、全部 nodes、`routing.py`、`state.py`、`schemas.py`、现有
`cases` 包、SQL migrations、Compose 以及退款工具都保持不变。

这保证新领域在影响客户流程前，先被独立、完整地测试。
